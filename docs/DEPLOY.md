# 젤리 던전 배포 안내 (구글 Apps Script)

> 개발을 잘 몰라도 따라 할 수 있게 쓴 안내서예요. **구글 계정 하나**와 **30분**이면 충분해요.
> 이 문서를 끝까지 따라 하면, 주소(링크) 하나로 누구나 휴대폰·태블릿·컴퓨터에서 게임을 할 수 있고,
> 게임이 끝난 뒤 점수가 **내가 가진 구글 스프레드시트**에 쌓여서 **랭킹**으로 보여요.

---

## 0. 먼저 알아 두기

| 말 | 쉬운 뜻 |
|----|---------|
| **Apps Script** | 구글이 공짜로 빌려주는 작은 서버예요. 게임 화면을 보여주고, 점수를 시트에 적어 줘요. |
| **웹 앱** | Apps Script 로 만든 "누구나 열 수 있는 웹페이지"예요. 주소가 하나 생겨요. |
| **배포** | 내가 쓴 코드를 "이 주소로 공개할게요" 하고 올리는 일이에요. |
| **스크립트 속성** | 코드 밖에 적어 두는 설정값이에요. (이 프로젝트는 `SHEET_ID` 하나만 써요. 안 적어도 돼요!) |
| **`/exec` 주소** | 배포한 버전으로 열리는 **진짜 주소**예요. 아이들에게 나눠 줄 주소는 이거예요. |
| **`/dev` 주소** | 내가 방금 고친 **최신 코드**를 나만 시험해 보는 주소예요. 남에게 주면 안 열려요. |

**게임 파일은 `src` 폴더 안에 있어요.** Apps Script 에 올릴 것은 딱 이 11개예요.

| 올릴 파일 | 종류 |
|-----------|------|
| `Code.gs` | 서버 코드 (점수 저장·랭킹) |
| `appsscript.json` | 프로젝트 설정 (웹 앱으로 쓰겠다는 설정) |
| `index.html` | 게임 틀 (아래 8개 파일을 끼워 넣어요) |
| `style.html`, `js_core.html`, `js_player.html`, `js_enemies.html`, `js_stage.html`, `js_ui.html`, `js_server.html`, `js_main.html` | 게임 화면·그림·규칙 |

> `docs`, `tools`, `prototype`, `GUIDE.md` 는 **올리지 않아요.** (만드는 사람용 자료예요.)

### 서버 없이 먼저 해 보고 싶다면
컴퓨터에서 `node tools/build-local.mjs` 를 실행하면 `dist/index.html` 이 만들어져요. 더블클릭하면 바로 게임이 열려요.
이때는 서버가 없어서 점수가 **그 기기 안에만** 저장돼요. ("내 기기에만 저장됐어요" 라고 보여요.)

## 1. 방법 A — 브라우저로만 하기 (설치 없음)

### A-1. (추천) 랭킹이 쌓일 구글 스프레드시트 먼저 만들기
1. <https://sheets.google.com> 에서 **빈 스프레드시트**를 만들어요. 이름은 `젤리 던전 랭킹` 처럼 알아보기 쉽게 해요.
2. 위쪽 메뉴에서 **확장 프로그램 → Apps Script** 를 눌러요. 새 탭에 편집기가 열려요.
   이렇게 열면 이 프로젝트가 시트에 **붙어 있어서(컨테이너 바인딩)** 아무 설정 없이 그 시트에 점수가 쌓여요.

> 시트를 먼저 만들기 싫다면 <https://script.google.com> → **새 프로젝트** 로 시작해도 돼요.
> 그러면 처음 저장할 때 `젤리 던전 랭킹` 시트가 내 구글 드라이브에 **자동으로** 만들어져요.
> (만든 시트 번호는 스크립트 속성 `SHEET_ID` 에 자동으로 기억돼요.)

### A-2. 파일 만들기
편집기 왼쪽의 **파일** 옆 **+** 버튼으로 파일을 만들고, `src` 폴더의 같은 이름 파일 내용을 **통째로 복사해서 붙여 넣어요.**

1. `Code.gs` 는 이미 있어요. 안의 내용을 지우고 `src/Code.gs` 내용으로 바꿔요.
2. **+ → HTML** 을 눌러 아래 9개를 하나씩 만들어요. **이름에 `.html` 을 붙이지 않아요!** (자동으로 붙어요)
   `index`, `style`, `js_core`, `js_player`, `js_enemies`, `js_stage`, `js_ui`, `js_server`, `js_main`
3. 이름 철자가 하나라도 다르거나 빠지면 게임이 열리지 않고 **Apps Script 오류 화면**이 나와요. (서버 코드 `include` 가 그 파일을 못 찾아 오류를 내기 때문이에요. 어느 파일 이름 때문인지는 편집기 왼쪽 **실행 내역**에서 확인해요.) 꼭 위 이름 그대로 써요. (대소문자·밑줄 포함)

> **더 쉬운 길:** 컴퓨터에서 `node tools/build-local.mjs` 를 실행하면 `dist/index.html` 에 게임이 **한 파일로 합쳐져** 나와요.
> 이 파일 내용을 `index` 하나에만 붙여 넣으면 나머지 8개 HTML 파일은 필요 없어요. (`Code.gs` 와 `appsscript.json` 은 그대로 필요해요.)
> 단, 게임을 고칠 때마다 다시 합쳐서 붙여 넣어야 해요. 자주 고친다면 방법 B(clasp)가 편해요.

### A-3. 프로젝트 설정(appsscript.json) 맞추기
1. 왼쪽 **프로젝트 설정(톱니바퀴)** 을 눌러요.
2. **"편집기에서 'appsscript.json' 매니페스트 파일 표시"** 에 체크해요.
3. 편집기로 돌아가 `appsscript.json` 을 열고 내용을 `src/appsscript.json` 으로 바꿔요.

```json
{
  "timeZone": "Asia/Seoul",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
  }
}
```

뜻: 한국 시간 사용 / 최신 자바스크립트(V8) / **"나(배포한 사람)의 권한으로 실행"** / **"로그인 없이 누구나 접속"**.
(이 두 설정 덕분에 아이들이 구글 로그인이나 권한 허용을 할 필요가 없어요.)

### A-4. 한 번 실행해서 권한 허용하기 (처음 한 번만)
1. 편집기 위쪽의 함수 선택 칸에서 **`setup`** 을 골라요.
2. **실행** 을 눌러요. **권한 검토** 창이 뜨면 아래 순서로 진행해요.
   1. 내 구글 계정을 골라요.
   2. **"Google에서 확인하지 않은 앱입니다"** 가 나오면 정상이에요. 내가 만든 앱이라 그래요. **고급** 을 눌러요.
   3. **"젤리 던전(안전하지 않음)으로 이동"** 을 눌러요.
   4. 요청하는 권한(스프레드시트 보기/수정)을 **허용** 해요.
3. 아래 **실행 로그** 에 `준비 끝! 랭킹이 저장되는 시트: https://docs.google.com/...` 이 나오면 성공이에요.
   그 시트를 열어 보면 `Scores` 탭에 머리글(`시간 | 닉네임 | 점수 | 별 | 난이도 | 스테이지 | 시간(초)`)이 있어요.

> 허용하는 권한은 "내 스프레드시트를 읽고 쓰기" 예요. 점수를 시트에 적어야 해서 필요해요.
> 이메일이나 연락처 같은 다른 것은 읽지 않아요.

### A-5. 웹 앱으로 배포하기
1. 오른쪽 위 **배포 → 새 배포** 를 눌러요.
2. **유형 선택(톱니바퀴) → 웹 앱** 을 골라요.
3. 아래처럼 채워요.
   - **설명:** `젤리 던전 1.0`
   - **다음 사용자로 실행:** **나**
   - **액세스 권한이 있는 사용자:** **모든 사용자**
4. **배포** 를 눌러요. 웹 앱 주소(`https://script.google.com/macros/s/…/exec`)가 나와요. **복사해 둬요!**
5. 새 탭에 붙여 넣어 열어 봐요. 게임 제목 화면이 나오면 성공이에요. 닉네임을 적고 한 판 해 봐요.
6. 게임이 끝나면 `✅ 저장됐어요!` 가 나오고, 시트의 `Scores` 탭에 한 줄이 생겨요.

## 2. 방법 B — clasp 로 한 번에 올리기 (컴퓨터에 익숙한 어른용)

`clasp` 는 구글이 만든 "내 컴퓨터의 폴더 → Apps Script 프로젝트" 업로드 도구예요. `src` 폴더를 통째로 올려 줘서, 고칠 때마다 한 줄이면 돼요.

```bash
# 1) 한 번만 설치·로그인 (Node.js 가 필요해요)
npm install -g @google/clasp
clasp login                       # 브라우저가 열리면 구글 계정으로 로그인
# 처음이라면 https://script.google.com/home/usersettings 에서 "Google Apps Script API" 를 켜요

# 2) 프로젝트 폴더에서 새 Apps Script 프로젝트 만들기 (src 폴더가 프로젝트의 루트)
cd seongmo-fight
clasp create-script --type webapp --title "젤리 던전" --rootDir src      # clasp 2.x 에서는: clasp create --type webapp ...
#   → 프로젝트 루트에 .clasp.json 이 생겨요 (안에 scriptId 가 있어요)
#   → 만약 src/appsscript.json 이 덮어써졌다면 `git checkout src/appsscript.json` 으로 되돌려요
#   (이미 만들어 둔 프로젝트에 연결하려면:  clasp clone-script <스크립트ID> --rootDir src     2.x: clasp clone ...)

# 3) 올리기
clasp push -f                     # src 폴더의 파일이 전부 올라가요 (docs, tools 는 안 올라가요)
#   -f(--force) 는 "설정 파일(appsscript.json)을 덮어쓸까요?" 질문 없이 덮어써요 (clasp 공식 안내에 `Forcibly overwrites the remote manifest` 라고 적혀 있어요). 질문이 뜨는 게 낫다면 `clasp push` 만 써도 돼요.

# 4) 한 번 실행해서 권한 허용 + 시트 준비 (편집기에서 하는 것이 가장 쉬워요)
clasp open-script                 # 편집기가 열려요 → 함수 `setup` 선택 → 실행 → 권한 허용 (위 A-4)      2.x: clasp open

# 5) 웹 앱으로 배포
clasp create-deployment --description "젤리 던전 1.0"                 # 2.x: clasp deploy --description "젤리 던전 1.0"
clasp list-deployments            # 배포 목록과 배포 ID 확인                                           2.x: clasp deployments
```

- 웹 앱 주소는 `https://script.google.com/macros/s/<배포 ID>/exec` 예요.
- 시트에 묶인 프로젝트로 쓰고 싶다면 방법 A-1 처럼 시트에서 **확장 프로그램 → Apps Script** 로 프로젝트를 만든 뒤, 그 프로젝트의 스크립트 ID 로 `clasp clone-script <스크립트ID> --rootDir src` 를 해요.
- **명령 이름은 clasp 버전마다 달라요.** clasp 3.x 에서 `open` → `open-script`, `create` → `create-script`, `clone` → `clone-script`, `deployments` → `list-deployments`, `deploy` → `create-deployment`, `deploy -i <ID>` → `update-deployment <ID>` 로 바뀌었어요. 위 표기는 clasp 공식 안내(<https://github.com/google/clasp>, `Command renames`)를 읽고 적은 거예요. 공식 안내에 "다른 이름들은 옛 이름도 계속 쓸 수 있다(alias)"고 적혀 있지만, **어느 옛 이름이 되는지는 확인하지 못했어요.** 내 컴퓨터의 버전은 `clasp --version`, 쓸 수 있는 명령은 `clasp --help` 로 확인해요.
- ⚠ `clasp push` 는 편집기에 있던 파일을 **통째로 덮어써요.** 편집기에서 직접 고친 게 있다면 먼저 `clasp pull` 로 받아 와요.
- **확인하지 못한 것:** 이 문서를 쓴 환경에서는 clasp 로 로그인해 실제로 올려 보지 못했어요. 그래서 위 명령들은 공식 안내와 맞춰 본 것이지, 직접 실행해 본 결과가 아니에요. `clasp create-script` 가 `src/appsscript.json` 을 새로 만들어 덮어쓰는지, `clasp push` 가 설정 파일을 덮어쓸지 묻는지는 버전에 따라 달라서 확인하지 못했어요. (그래서 위에 되돌리는 방법을 적어 뒀어요.)
- `.clasp.json` 에는 내 프로젝트 ID 가 들어 있어요. 비밀번호는 아니지만 공개 저장소에 올릴 필요는 없어요.

## 3. 스크립트 속성 (안 해도 돼요!)

기본은 아무 설정 없이 동작해요. 랭킹 시트를 **내가 정한 파일로** 쓰고 싶을 때만 해요.

1. 편집기 왼쪽 **프로젝트 설정(톱니바퀴)** → 아래쪽 **스크립트 속성** → **스크립트 속성 추가**
2. 속성 `SHEET_ID`, 값은 시트 주소 속 긴 글자예요.
   `https://docs.google.com/spreadsheets/d/`**`여기_긴_글자`**`/edit`
3. 저장해요. 그 파일 안에 `Scores` 탭이 없으면 자동으로 만들어 줘요.

시트를 고르는 순서는 이래요.

1. 스크립트 속성 `SHEET_ID` 가 있으면 그 시트
2. 없으면 프로젝트가 붙어 있는 시트 (방법 A-1)
3. 그것도 없으면 `젤리 던전 랭킹` 시트를 새로 만들고, 그 번호를 `SHEET_ID` 에 **자동으로 적어 둬요**

> `SHEET_ID` 가 적혀 있는데 시트를 열 수 없으면(지웠거나 번호가 틀림) **새 시트를 몰래 만들지 않고** 오류로 알려요.
> 그래야 예전 기록이 사라진 줄 모르고 지나가는 일이 없어요. 번호를 고치거나 속성을 지우면 돼요.

## 4. 코드를 고친 뒤 다시 배포하기 (제일 헷갈리는 부분!)

**편집기에서 코드를 저장하는 것만으로는 `/exec` 주소의 게임이 바뀌지 않아요.** 새 버전을 만들어 **같은 배포에 덮어써야** 해요.

1. **배포 → 배포 관리**
2. 고치려는 배포 옆 **연필(수정)** 아이콘
3. **버전:** → **새 버전** 선택, 설명을 적어요 (예: `1.1 보스 쉬워짐`)
4. **배포**

그러면 **주소는 그대로**이고 안의 게임만 새 버전이 돼요. 아이들에게 새 링크를 줄 필요가 없어요.

> ⚠ **배포 → 새 배포** 를 또 누르면 **완전히 새 주소**가 생겨요. 예전 주소는 옛 버전으로 그대로 남아요.
> (옛 주소로 들어온 사람은 옛 게임을 보게 돼요.) 일부러 그러는 게 아니라면 "배포 관리 → 수정" 을 써요.

| 주소 | 어떤 코드가 실행되나요 | 누가 열 수 있나요 | 언제 쓰나요 |
|------|----------------------|------------------|-------------|
| `…/exec` | **배포한 버전** (새 버전을 만들어야 바뀜) | 모든 사람 | 아이들에게 나눠 줄 진짜 주소 |
| `…/dev` | **저장한 최신 코드** (바로 바뀜) | 편집 권한이 있는 나 | 고친 것을 바로 시험할 때 (**배포 → 배포 테스트**) |

clasp 를 쓴다면: `clasp push` 로 올린 뒤 `clasp list-deployments`(2.x: `clasp deployments`) 로 배포 ID 를 확인하고
`clasp update-deployment <배포 ID> --description "1.1"`(2.x: `clasp deploy --deploymentId <배포 ID> --description "1.1"`) 로 **같은 배포를 갱신**해요.
(배포 ID 를 안 쓰고 `create-deployment`/`deploy` 만 하면 새 배포, 즉 새 주소가 생겨요. 이 명령들도 직접 실행해 보지는 못했어요: 위 clasp 안내 참고.)

## 5. QR 코드로 나눠 주기

아이들이 긴 주소를 치지 않게 QR 코드를 만들어 줘요.

- **컴퓨터 크롬:** `/exec` 주소로 들어간 뒤 주소창 오른쪽 **공유 아이콘 → QR 코드 만들기** → **다운로드** 해서 인쇄하거나 화면에 띄워요.
- **안드로이드 크롬:** 점 3개 메뉴 → **공유 → QR 코드**
- 나눠 주기 전에 **다른 기기(내 휴대폰)로 QR 을 찍어서** 게임이 열리는지, 점수가 저장되는지 꼭 확인해요.
- 아이들이 쓰는 기기는 **화면을 가로로** 돌리고, 처음 한 번 **「시작!」** 버튼을 눌러야 소리가 나요. (브라우저 규칙이에요)

## 7. 사용량 한도 (쿼터)

Apps Script 는 공짜인 대신 **사용 한도**가 있어요. 정확한 숫자는 구글이 가끔 바꾸니 꼭 공식 문서에서 확인해요.
공식 문서: <https://developers.google.com/apps-script/guides/services/quotas>

- **동시에 실행되는 개수**(simultaneous executions)에 한도가 있어요. 이 글을 쓸 때 문서에는 "사용자당 30개" 라고 되어 있었어요.
  이 게임은 **게임 화면은 한 번 불러오고, 점수 저장·랭킹 조회 때만** 서버를 쓰기 때문에 한 반(수십 명) 정도는 보통 괜찮아요.
- 점수를 저장할 때는 **한 번에 한 명씩** 줄을 서서 시트에 써요. (겹쳐 쓰다가 줄이 섞이는 것을 막으려고요)
  줄을 서는 시간을 줄이려고, 잠긴 동안에는 **시트에 한 줄 쓰는 일만** 하고(등수 계산처럼 시트 전체를 읽는 일은 잠금을 푼 뒤에 해요), 잠금을 기다리는 시간은 **최대 6초**예요. (게임 쪽 서버 호출 제한 10초보다 짧아서, 너무 바쁘면 "바빠요" 신호가 먼저 도착해 한 번 더 시도해요.)
  한 반 전원이 **같은 순간에** 저장을 누르면 뒷사람은 몇 초 기다려야 해요. 그동안 못 쓰면 `📱 내 기기에만 저장됐어요` 가 나올 수 있어요. 점수는 그 기기에 남아 있으니, **`다시 보내 볼까요?`(다시 시도) 단추가 보이면 눌러 보고**, 없으면 한 판 더 하면 돼요. → "다 같이 동시에 누르지 말고 한 줄씩" 안내해 줘요.
- **저장 요청이 1분에 300번**을 넘으면 서버가 잠금을 잡기 전에 "바빠요" 로 돌려보내요. (반 하나가 한꺼번에 눌러도 한참 못 미치는 숫자예요. 누가 일부러 저장을 마구 부르는 장난을 해도 진짜 저장이 밀리지 않게 하는 안전장치예요.)
- **누구나 저장 요청을 보낼 수 있어요.** 점수는 로그인·인증 없이 받는 값이라서, 마음먹고 브라우저 도구로 저장을 반복 호출하면 시트에 줄이 많이 쌓일 수 있어요. 시트가 지저분해지면 **어른이 시트에서 해당 줄을 지워 주세요.** (랭킹은 30초 안에 반영돼요.)
- 랭킹은 **30초 동안 기억**해 두었다가 보여줘요. 그래서 조회가 많아도 시트를 매번 읽지 않아요. (점수가 저장되면 기억을 바로 지워요.)
- 구글 서비스 점검·일시 오류가 있을 수 있어요. 그때도 게임은 멈추지 않고, 점수는 **그 기기에 먼저 저장**돼요.
- 시트는 저장할 때마다 **한 줄씩 늘어나요.** (점수 0 인 판도 한 줄이에요.) 몇 천 줄이 넘어 느려지면 오래된 줄을 지워 줘요. (랭킹은 닉네임별 최고 점수만 보여줘요.)
- 시트를 만들 때 빈 줄을 3000줄쯤 미리 만들어 두고 닉네임·스테이지 칸을 `글자` 서식으로 맞춰 둬요. (`007`, `1e3`, `TRUE` 같은 이름이 숫자나 참/거짓으로 바뀌지 않게요.) 기록이 쌓여 **남은 빈 줄이 200줄 밑**이 되면 편집기에서 **`setup` 을 다시 실행**해요. 빈 줄을 늘리고 서식을 다시 맞춰 줘요. (자동으로 해 주지는 않아요. 줄이 새로 생길 때 서식이 이어지는지는 시트가 알아서 하는 일이라 확인하지 못했어요.)

## 9. 운영 팁

### 랭킹 관리
- **이상한 닉네임 지우기:** 시트 `Scores` 탭에서 그 줄을 지워요. (최대 30초 뒤 랭킹에서도 사라져요.)
- **랭킹 초기화:** 머리글(1행)만 남기고 아래 줄을 전부 지워요. 머리글을 지웠다면 편집기에서 **`setup` 을 실행**해 다시 만들어요. (손으로 쓰려면 `시간 | 닉네임 | 점수 | 별 | 난이도 | 스테이지 | 시간(초)` 순서예요.)
- **시트는 가끔 훑어봐요.** 금칙어 목록은 완벽하지 않아서, 어른이 이상한 이름이 없는지 가끔 봐 주면 좋아요.
- 점수는 **기기가 보내 주는 값**이라, 마음먹고 속이면 고칠 수 있어요. (서버가 범위·모양과 "말이 되는 기록인지"는 검사하지만 "진짜 그렇게 쳤는지"는 알 수 없어요. 아래 점수 규칙 참고.) 아이들끼리 즐기는 용도로는 충분해요.

### 금칙어 규칙 (아이들이 보는 공개 랭킹이라서 꼼꼼히 걸러요)
닉네임은 저장하기 전에 **화면(게임)과 서버가 똑같은 규칙으로 두 번** 검사해요. 순서는 이래요.

1. **정리:** 눈에 안 보이는 글자(한글 채움 문자, 폭 없는 공백 등)를 지우고, 글자를 표준 모양(NFC)으로 맞추고, 공백을 정리하고, 맨 앞의 `= + - @` 를 지워요. (시트 수식으로 읽히는 것을 막으려고요.)
2. **글자 종류:** 숫자, 영어, 한글(완성형), **눈에 보이는 한글 자모**(`ㅋㅋ`, `ㅠㅠ` 등)와 공백만 써요. 한글 채움 문자나 옛 자모는 안 돼요. (빈 이름이나 금칙어 사이에 끼워 넣는 데 쓰이니까요.)
3. **길이:** 2~8글자.
4. **금칙어:** 아래 규칙으로 찾아요.

금칙어를 찾는 방법은 이래요.

- **띄어쓰기는 없는 셈**이에요: `f u c k`, `시 발` 도 걸려요. 숫자를 글자 대신 쓴 것(`sh1t`, `hit1er`)과 숫자를 끼워 넣은 것(`시1발`), 사이에 낀 `ㅋ` `ㅎ`(`시ㅋ발`)도 걸러요.
- **소리가 비슷하거나 글자를 풀어 쓴 것도 같게 봐요:** 한글은 자모로 풀어서 비교해서, `시발` = `씨발` = `씨빨` = `ㅅㅣ발` = `시ㅂㅏㄹ` = `ㅅㅣㅂㅏㄹ` = `시이발`(`ㅣ` 를 늘여 쓴 것). 영어는 같은 글자를 늘여 써도(`fuuuck`) 걸려요.
  - 목록에 **예사소리(`ㅅ ㅂ ㄱ ㄷ ㅈ`)로 적은 낱말은 된소리(`ㅆ ㅃ ㄲ ㄸ ㅉ`)로 쓴 것도** 걸러요. 거꾸로 **된소리로 적은 낱말은 된소리로 쓴 것만** 걸러요. (예: `찐따` 는 걸리지만 `진달래` 는 괜찮아요.)
  - 글자와 글자 사이는 이어 붙어 보여도 넘어가지 않아요: `시바람`, `조나단` 은 괜찮아요. 마지막 글자에 받침이 더 붙은 것도 다른 글자로 봐요: `창녀` 는 걸리고 `창녕` 은 괜찮아요.
  - 자음만 쓴 줄임말(`ㅅㅂ`, `ㅂㅅ`, `ㅁㅊ` …)은 이름 속에 **자음 낱글자로 쓴 것만** 찾아요. `옷방`, `없는` 처럼 글자 속 받침이 이어 붙어 보이는 것은 괜찮아요.
  - 첫 글자만 자음으로 쓴 것(`ㅅ발`, `ㅂ신`, `ㅁ친`, `ㅈ같` …)도 **홀로 쓴 자음일 때만** 걸러요. `옷발`, `밥신` 처럼 앞 글자의 받침은 괜찮아요.
- **목록은 둘이에요.** (1) 이름 어디에 들어 있어도 거르는 낱말, (2) **이름 전체가 이 낱말일 때만** 거르는 낱말(뜻이 둘이거나 다른 낱말 속에 흔히 들어 있는 짧은 말: `보지`, `자지`, `걸레`, `시바`, `새끼`, `ass`, `gay` 등). 두 번째는 숫자·띄어쓰기·`ㅋㅋ ㅎㅎ ㅠㅠ` 를 빼고 비교해서 `보지`, `보 지`, `보지ㅋㅋ`, `보지2` 는 걸리고, `보지마`, `보지 못함`, `걸레질`, `grape`, `class`, `Dickens` 는 통과해요.
- **정해 둔 판단:** `시바견`, `시바이누` 는 통과하고 `시바`(와 `씨바`)만 걸려요. 알려진 **일부러 막은 오탐**: `시발점`, `병신년`, `꺼져라용`, `쫒아`(`쫓아` 의 틀린 맞춤법이 `좆` 으로 읽혀요. 맞게 쓴 `쫓아` 는 괜찮아요), `Essex`/`Sussex`(`sex`), `Peniston`(`penis`), `pussycat`, `Shiitake` 는 걸려요. `검둥이`(강아지 이름으로 흔해요)는 통과하고 `깜둥이`(비하 표현)만 걸려요. 아이들 안전이 먼저라서 그대로 두었어요. (괜찮은 이름이 잘못 걸린다고 느끼면 아래 "금칙어 고치기"에서 고쳐요.)
- **한글이 섞인 이름은 엉뚱한 자모·영어를 빼고도 봐요:** `시ㅇ발`(낱글자 자모 `ㅇ` 를 끼움), `시a발`(영어를 끼움), `fㅇuck` 도 걸려요. 숫자·띄어쓰기·`ㅋㅎ` 끼워 넣기와 같은 원리예요.
- **완벽하지 않아요.** 다른 **완성형 한글 글자**를 끼워 넣은 것(`시가발`), 새로 생긴 은어, 목록에 없는 말은 못 걸러요. **어른이 가끔 랭킹을 훑어봐 주세요.** 이상한 이름은 시트에서 그 줄을 지우면 돼요.
- 걸러 내지 못하는 것: 실명·학교·전화번호처럼 **개인정보가 닉네임이 되는 것**. 아이들에게 "별명을 써요" 라고 알려 주세요. (게임의 🎲 단추는 `말랑젤리37` 같은 안전한 별명을 만들어 줘요.)

### 금칙어 고치기
금칙어 목록은 **두 곳에 똑같이** 있어야 해요. (화면에서 먼저 알려 주고, 서버가 한 번 더 막아요.)
- `src/js_server.html` 안의 `NICKNAME_BLOCKLIST`(어디에 들어 있어도) 와 `NICKNAME_BLOCKLIST_WHOLE`(이름 전체일 때만)
- `src/Code.gs` 안의 `BLOCKLIST_` 와 `BLOCKLIST_WHOLE_`

`// ==== BLOCKLIST START ====` 와 `END` 표시 사이의 배열에 단어를 한 줄 추가해요. (영어는 소문자·띄어쓰기 없이, 한글은 **예사소리로** 적으면 된소리도 같이 걸려요. 소리가 비슷한 낱말을 따로 더 적을 필요는 없어요.)
정리·찾기 도구(`// ==== NICK-FILTER START ====` 블록)는 **두 파일에 글자 하나까지 똑같아야** 해서, 고칠 일이 있으면 한쪽만 고치지 말고 두 파일을 같이 고쳐요.
`node tools/tests/code-gs.test.mjs` 를 실행하면 두 목록과 도구가 같은지, 걸려야 하는 이름 280여 개와 괜찮아야 하는 이름 180여 개가 그대로인지 검사해 줘요. (새 단어 때문에 괜찮은 이름이 걸리면 이 테스트가 알려 줘요.)

### 점수 규칙 (서버가 다시 검사해요)
닉네임 2~8자(한글·영어·숫자·공백) / 점수 0~**99999** 정수 / 별 0~3 / 난이도 `easy·normal·hard` / 시간 0~86400초 / 스테이지는 `stage1` (스테이지를 늘리면 `Code.gs` 의 `STAGE_IDS_` 와 `js_server.html` 의 `stageIds` 에도 추가).
**말이 되는 기록만 받아요:** 별은 **클리어한 판에만**(별이 1개 이상이면 클리어여야 해요), **클리어한 판은 45초 이상**, 모르는 스테이지 이름은 거절. 진짜 게임에서는 늘 지켜지는 규칙이라 정직한 기록은 걸리지 않아요. 브라우저 도구로 `999999점` 같은 값을 보내는 것은 막혀요. 하지만 99999점 이하의 그럴듯한 값을 만들어 보내는 것까지는 막을 수 없어요. (서버가 게임을 다시 해 볼 수는 없으니까요.)
같은 닉네임이 **10초 안에 같은 점수**를 또 보내면(더블클릭·재시도) 한 번만 저장해요.
랭킹은 **닉네임별 최고 점수**(영어 대소문자는 같은 이름으로 봐요)를 높은 순으로, 같으면 **먼저 달성한 쪽이 위**예요.

### 시트의 열
`시간 | 닉네임 | 점수 | 별 | 난이도 | 스테이지 | 시간(초)` — 이름과 점수 같은 **게임 숫자만** 있어요.

## 10. 아이들 개인정보 안내 (꼭 읽어 주세요)

**이 게임이 저장하는 것:** 닉네임, 점수, 별 개수, 난이도, 스테이지 이름, 플레이 시간(초), 저장한 시각. **그게 전부예요.**

**이 게임이 저장하지 않는 것:** 이름·이메일·전화번호·학교·나이·사진·위치. 접속한 사람의 구글 계정이나 IP 주소도 코드가 읽지 않고 저장하지 않아요.
(그런 정보를 읽는 기능을 코드에서 일부러 쓰지 않았고, 테스트가 이를 확인해요. 다만 구글이 서비스 운영을 위해 **자체적으로** 쌓는 기록은 구글의 정책을 따라요.)

**구글 폰트 (외부 요청 하나):** 게임 화면의 글꼴 `Jua`(귀여운 글꼴)를 **구글 폰트**(`fonts.googleapis.com`, `fonts.gstatic.com`)에서 불러와요. 그래서 페이지를 여는 순간, 아이가 아무것도 누르기 전에 그 아이의 **브라우저가 구글 폰트 서버에 요청**을 보내요. (이때 구글 폰트 서버가 접속 기기의 IP 주소와 브라우저 종류 정보를 받아요. 우리 코드는 읽지도 저장하지도 않아요.) 게임이 쓰는 **유일한 외부 요청**이에요.
- 게임을 구글 Apps Script 로 배포하면 페이지 자체를 구글이 내려 주기 때문에 추가로 드러나는 정보는 적어요.
- 하지만 `node tools/build-local.mjs` 로 만든 한 파일을 **학교 서버·GitHub Pages 같은 다른 곳에 올려 쓰면**, 그 곳에서 접속한 아이들의 정보가 구글 폰트로 가요. 학교·기관 규정(개인정보 담당자)에 맞는지 확인해 주세요. (만 14세 미만 아동에게는 더 조심해야 해요.)
- **없애는 법:** `src/style.html` 맨 위쪽의 `<link>` 세 줄(`fonts.googleapis.com` 과 `fonts.gstatic.com` 이 들어 있는 줄)을 지우면 외부 요청이 사라져요. 글꼴만 시스템 한글 글꼴(맑은 고딕, Apple SD Gothic Neo 등)로 바뀌고 게임은 그대로 동작해요. (이 안내를 쓴 시점에는 이 줄을 지우지 않고 그대로 두었어요. 지우고 싶으면 위처럼 직접 지워요.)

**왜 이렇게 만들었나요?**
- 우리나라 **개인정보 보호법**은 **만 14세 미만 아동**의 개인정보를 처리하려면 **법정대리인(보호자)의 동의**를 받도록 해요.
  이 게임은 처음부터 **개인정보를 받지 않아서** 동의 절차가 필요 없도록 만들었어요.
  (법 조항과 내용은 바뀔 수 있어요. 학교·기관에서 쓰기 전에는 최신 내용을 [국가법령정보센터](https://www.law.go.kr)나 개인정보 담당자에게 확인해 주세요. 이 문서는 법률 자문이 아니에요.)

**어른이 꼭 해 주세요:**
1. 아이들에게 **"진짜 이름 말고 별명(닉네임)을 써요"** 라고 알려 줘요. 실명, 학교, 전화번호가 닉네임이 되면 그때부터는 개인정보가 될 수 있어요. (닉네임 검사기는 이런 것까지 알아채지 못해요.)
2. 닉네임은 **랭킹에 모두에게 보여요.** 보여도 괜찮은 이름만 쓰게 해요. (게임의 🎲 단추는 `말랑젤리37` 처럼 귀여운 낱말 둘과 숫자 두 개로 안전한 별명을 만들어 줘요.)
   - **같은 닉네임은 랭킹에서 한 줄을 같이 써요.** 반에 `용사` 가 둘이면 점수가 높은 쪽 한 줄만 보이고, 점수가 낮은 아이도 "내 이름이 1등" 으로 보일 수 있어요. (닉네임 말고는 누구인지 구별하는 정보를 일부러 받지 않기 때문이에요.) 아이들에게 **숫자를 붙이거나 🎲 단추로 만든 이름**을 쓰게 하면 거의 겹치지 않아요.
3. 스프레드시트를 **다른 사람과 공유하지 않아요.** (공유하면 닉네임 목록이 보여요.) 시트는 만든 사람 계정에만 보여요.
4. 시트의 **기록을 지울 수 있다**는 것(보호자가 삭제를 원하면 해당 닉네임 줄을 지우면 돼요)을 알아 둬요.
5. 서비스 안내 글(QR 옆)에 "닉네임과 점수만 저장돼요" 라고 한 줄 적어 두면 좋아요.
6. 아이들이 오래 하지 않게 해요. 게임은 30분마다 "잠깐 쉬어요!" 알림을 보여줘요.

## 11. 한 장 요약

1. 시트 만들기 → **확장 프로그램 → Apps Script**
2. `Code.gs` + `appsscript.json` + HTML 9개 붙여 넣기 (또는 `clasp push`)
3. 함수 `setup` **실행** → 권한 **허용**
4. **배포 → 새 배포 → 웹 앱** (나로 실행 / 모든 사용자) → `/exec` 주소 복사
5. QR 코드로 나눠 주기 → 한 판 해 보고 시트에 줄이 쌓이는지 확인
6. 고친 뒤에는 **배포 관리 → 수정 → 새 버전 → 배포** (주소는 그대로!)
